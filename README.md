# Домашнее задание: Gradle и JUnit

Репозиторий: [Q2016test/t1module](https://github.com/Q2016test/t1module).

Проект по теме 2 курса. Gradle 8.14.3, JUnit Jupiter 5.13.4, Java 8 или новее.

## Запуск

Установите JDK и задайте `JAVA_HOME`. Отдельно устанавливать Gradle не нужно:
проект содержит Gradle Wrapper. При первом запуске необходим доступ к интернету
для загрузки Gradle и зависимостей из Maven Central.

Windows PowerShell:

```powershell
.\gradlew.bat clean test
```

Linux / macOS:

```sh
bash gradlew clean test
```

HTML-отчёт: `build/reports/tests/test/index.html`.

## Задачи Gradle

В `build.gradle` настроены две задачи:

1. `test` запускает все тесты JUnit и показывает их вывод в консоли. При каждом
   запуске тесты выполняются заново, чтобы использовать новые случайные данные.
2. `testRunFinished` выводит `Test run is over`. Она связана с первой задачей через
   `finalizedBy` и выполняется после неё, в том числе при падении теста.

Общий класс `TestLifecycle` с `@BeforeEach` и `@AfterEach` выводит для каждого
теста, повтора и набора параметров:

```text
========================Test method start
...вывод теста...
Test method end
========================
```

`TestResult.check` сравнивает результат с эталоном через `if` и печатает
`TEST PASSED` или `TEST FAILED`. При несовпадении он также бросает исключение,
чтобы JUnit и Gradle зафиксировали неуспешный тест. `assert` и JUnit Assertions
не используются.

## Задача 1 — лекция

`LectureTest` содержит три тестовых метода:

| Метод | Аннотация | Данные |
| --- | --- | --- |
| `isEven` | `@Test` | Одно случайное число от 1 до 100 |
| `checkAccess` | `@RepeatedTest(20)` | Случайный возраст от 0 до 99 для каждого повтора |
| `getGrade` | `@ParameterizedTest` + `@MethodSource` | Массив из 10 случайных чисел от 0 до 100 |

Все границы случайных диапазонов включены.

## Задача 2 — вебинар

`BasicJava` содержит все 12 методов из присланного ДЗ «Базовая Java».
Для них написаны ровно 12 тестовых методов: по четыре с каждой аннотацией.

| Класс | Аннотация | Проверяемые методы |
| --- | --- | --- |
| `WebinarSingleTest` | `@Test` | `isEven`, `isPositive`, `hasBug`, `reverse` |
| `WebinarRepeatedTest` | `@RepeatedTest(20)` | `checkAccess`, `blastOff`, `findMax`, `calcAverage` |
| `WebinarParameterizedTest` | `@ParameterizedTest` | `getGrade`, `sumToN`, `getEvenInRange`, `removeSpecificName` |

Входные данные генерируются случайно или читаются из CSV в `src/test/resources`.
Ожидаемые значения берутся из CSV или вычисляются независимо от проверяемых
методов: например, максимум определяется сортировкой копии массива,
разворот — через `Collections.reverse`, сумма — по формуле арифметической
прогрессии. Тесты не используют проверяемые методы для расчёта эталона.

CSV покрывают ноль, отрицательные значения, возраст 18 и 19, все границы
оценок, пустой и обратный диапазон, крайние значения `int`, повторяющиеся имена
и `null`. В `names.csv` имена внутри ячейки разделены `;`, пустая ячейка
обозначает пустой список, а `NULL` — значение `null`.

Для `reverse` и `removeSpecificName` дополнительно проверяется, что метод
возвращает новый массив/список и сохраняет исходные данные. Массивы сравниваются
по содержимому. Каждый результат сравнения выводит `TEST PASSED` либо
`TEST FAILED`; при успешном прогоне сообщений `TEST FAILED` нет.

Сохранены условия предыдущего ДЗ: доступ разрешён **строго после 18 лет**;
`isPositive(0)` возвращает `true`; `getGrade` использует интервалы 0–20 → E,
21–40 → D, 41–60 → C, 61–80 → B, 81–100 → A, иначе возвращает `Error`.

Всего в проекте 15 тестовых методов: 3 для лекции и 12 для вебинара.
С учётом повторов и наборов параметров выполняется 195 запусков JUnit.

Можно запустить части отдельно:

```powershell
.\gradlew.bat test --tests ru.homework.LectureTest
.\gradlew.bat test --tests 'ru.homework.Webinar*'
```
